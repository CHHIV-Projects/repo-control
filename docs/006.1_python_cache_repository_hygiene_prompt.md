# Milestone 006.1 — Python Cache / Repository Hygiene

Prompt file:

`006.1_python_cache_repository_hygiene_prompt.md`

Required closeout file:

`006.1_python_cache_repository_hygiene_closeout.md`

## Objective

Remove generated Python bytecode/cache artifacts from Repo Control Plane Git tracking and prevent normal Python execution, tests, and compile validation from creating misleading repository changes.

This milestone exists because Milestone 006 validation exposed tracked/generated artifacts such as:

    __pycache__/
    *.pyc

which were recreated by ordinary Python activity and appeared in Git status.

That behavior is undesirable for Repo Control Plane because future Git-workflow functionality depends on distinguishing:

    intentional source changes

from:

    generated runtime/test artifacts

Milestone 006.1 is repository hygiene only.

Do not add new Repo Control Plane product functionality.

# Gate A — Determine Exact Existing Cache Footprint

Before changing `.gitignore` or Git tracking, establish the current Python-generated cache footprint.

Use Git-derived evidence to identify tracked files matching Python bytecode/cache patterns.

At minimum inspect for tracked:

    *.pyc
    *.pyo
    __pycache__/*

Use tracked-file evidence such as:

    git ls-files

rather than relying only on filesystem discovery.

Also inspect the working tree for currently existing Python cache artifacts.

Report:

- total tracked generated cache files;
- tracked cache paths;
- whether any `__pycache__` directory contents are tracked;
- existing relevant `.gitignore` rules;
- whether any tracked file under these patterns appears not to be ordinary generated Python bytecode.

If any tracked cache-looking file appears intentionally maintained rather than generated:

    STOP — ESCALATION REQUIRED

Do not delete it based merely on its filename.

The expected case is ordinary CPython-generated cache artifacts.

---

# Gate B — `.gitignore` Contract

Ensure the repository ignores ordinary generated Python bytecode/cache artifacts.

At minimum the resulting ignore behavior must cover:

    __pycache__/
    *.py[cod]

Equivalent minimal standard Python ignore rules are acceptable.

Do not add unrelated broad ignore rules merely because this file is being edited.

Do not broadly copy a large generic Python `.gitignore` template.

This milestone is specifically about generated Python bytecode/cache noise.

If the repository has no `.gitignore`, create a small one containing only the necessary rules.

If one already exists, extend it minimally.

Do not ignore:

- Python source files;
- tests;
- documentation;
- project configuration;
- deterministic Repo Control Plane state that belongs outside the repository anyway.

---

# Gate C — Remove Generated Cache Artifacts From Git Tracking

Remove confirmed generated Python bytecode/cache artifacts from Git tracking.

The desired final Git state is:

    zero tracked *.pyc / *.pyo files
    zero tracked files inside __pycache__ directories

Removing generated cache files from the repository is authorized in this milestone.

Do not remove source `.py` files.

Do not remove tests.

Do not remove package `__init__.py` source files.

Be particularly careful to distinguish:

    __init__.py

from:

    __init__.cpython-312.pyc

or similar generated bytecode.

Use the smallest safe Git/index cleanup necessary.

Do not perform:

- branch changes;
- resets;
- rebases;
- merges;
- pushes;
- unrelated repository cleanup.

The coder may use ordinary Git staging/index operations required to remove these generated tracked files as part of the milestone implementation, but must not commit or push without separate instruction.

# Gate D — Verify Ignore Behavior

After `.gitignore` and tracking cleanup:

1. delete existing generated Python cache artifacts from the working tree where useful for a clean validation start;
2. confirm the intended tracked/source files remain intact;
3. confirm zero Python cache files remain tracked.

Required tracked-file check should establish the equivalent of:

    git ls-files

returning no:

    *.pyc
    *.pyo
    */__pycache__/*

Then allow ordinary Python activity to recreate caches.

Do not depend solely on:

    PYTHONDONTWRITEBYTECODE=1

for acceptance.

The point of this milestone is that ordinary Python execution may create caches without creating Git noise.

# Gate E — Ordinary Test Execution Must Not Dirty Git

Run the full existing Repo Control Plane test suite using normal Python behavior.

At minimum:

    PYTHONPATH=src python3 -m unittest -q

Do NOT set:

    PYTHONDONTWRITEBYTECODE=1

for this specific hygiene validation.

The test run may create:

    __pycache__
    *.pyc

on disk.

Afterward:

    git status --short

must show no cache-related changes.

Any remaining status entries should be only the intentional Milestone 006.1 changes themselves:

- `.gitignore` if modified/added;
- removal of previously tracked generated cache files;
- closeout documentation.

No source/test files should change merely because the test suite ran.

All tests must pass.

# Gate F — Compile Validation Must Not Dirty Git

Capture Git status before and after compile validation and confirm that no new tracked/staged/unstaged cache churn appears.
