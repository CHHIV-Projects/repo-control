## 10. root cause

Root cause: inconsistent canonical sort contract between prepare and verify paths.

- Prepare path sorted staged raw records by path-first key.
- Pre-fix verify path sorted committed raw records by full raw-byte lexical order.

This caused false-negative fingerprint mismatch for multi-file commits where path order and raw-byte lexical order diverged.

## 16. exact remediation

In `commit_execution._parse_raw_records(...)`, changed canonical sort to match prepare-time semantics:

- from raw-byte lexical `records.sort()`
- to path-first deterministic sort with metadata tie-break:
  - `records.sort(key=lambda item: (path_bytes, metadata_bytes))`

No semantic fields were ignored; no fuzzy logic introduced.

## 17. canonicalization/equality contract after fix

Canonical comparison contract is now consistent:

1. Represent each raw diff record as `metadata + "\t" + path` bytes.
2. Canonically order records path-first (byte ordering), metadata second.
3. Build fingerprint with fixed prefix `repoctl-staged-delta-v1\0` and NUL-separated records.
4. Require exact fingerprint equality.
