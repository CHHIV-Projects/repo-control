## 27. known limitations/deferred items

Deferred by design from 009.3:

- repository chooser/registry
- persistent snapshot purpose labels
- automatic snapshot boundary creation
- code-lineage model
- strict coder-context freshness authority
- Milestone Record model
- Architect Packet/export
- upstream fetch/refresh mutation workflow
- guarded push
- browser Stage/Commit controls (M010 boundary)
- whitespace diagnostics/normalization
- service-style startup/tunnel automation

Architectural finding recorded during Product Owner context reconciliation:

- `context_id` is canonical-query-derived within a repository evidence slot, not repository-state-derived.
- Within one repository evidence slot, one `context_id` maps to one current persisted payload.
- Regenerating the same canonical query replaces that persisted payload for the same `context_id`.
- Therefore, `context_id` alone is not an immutable historical repository-state evidence identity.
- Future strict coder freshness / Architect handoff / milestone lineage should use a stronger repository-state-bound identity or a versioned evidence model.
