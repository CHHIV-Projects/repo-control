# Ollama Envelope Parsing Contract

The provider must treat the native Ollama response as two separate structured layers.

## Layer 1 — Ollama Envelope

The HTTP response body must first parse as JSON.

Require the expected response envelope sufficiently to locate:

    message.content

Do not interpret the entire Ollama response envelope as the GPT-OSS analysis object.

Provider telemetry such as durations or token counts is not analysis evidence.

## Layer 2 — Structured Model Content

Then parse:

    message.content

as the GPT-OSS structured JSON result.

Whitespace surrounding the JSON string may be ignored.

Do NOT:

- extract JSON from Markdown fences;
- search for the first `{`;
- strip arbitrary prose;
- repair malformed JSON;
- ask the model to repair itself;
- silently transform protocol debris into JSON.

If `message.content` is not valid JSON:

    fail closed.

The structured-output API should produce structured content; Repo Control Plane should not build a permissive recovery parser around malformed generation.
